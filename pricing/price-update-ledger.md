# 黑曜報價更新工作簿

這是報價抓取、人工審閱與正式發布分頁共用的交接紀錄。任何分頁開始處理報價前，必須先讀取本文件與 `release-manifest.json`。

## 權責與狀態

狀態依序為：

```text
抓取中 → 待比對 → 待人工確認 → 待發布審核
  → 已可提交 GitHub，但尚未上傳及發布
  → 已提交 GitHub／發布中
  → 已發布

待人工確認／待發布審核
  ↘ 退回修正
  ↘ 待網站／政策異動
```

- 抓價分頁可以建立批次、整理差異並提出建議，最高只能標示為「待發布審核」。
- 使用者核准、例外處理、結構判定與資料驗證完成後，發布分頁才能將許可檔標成 `approved`。它的固定中文顯示是「已可提交 GitHub，但尚未上傳及發布」。
- GitHub Actions 只有讀到 `approved`，且所有門檻通過時，才會發布 Cloudflare Pages。
- 發布成功後，由發布分頁把工作簿與許可檔更新為「已發布」。
- 不得把 `approved` 寫成「已上傳」或「已發布」；Git commit、push 與 Cloudflare 部署都必須有實際結果才能升級狀態。

## 新增、刪除與改名判定

| 來源差異 | 判定 | 處理方式 |
| --- | --- | --- |
| 既有品牌、既有產品類別下新增型號 | `data-only` | 可新增型號與報價，不升級網站版本 |
| 既有型號新增可對應既有維修分類的項目 | `data-only` | 可新增報價項目 |
| 新品牌，但現有品牌下拉選單可動態產生 | `policy-review-required` | 先提案品牌名稱、中文別名、排序與承接範圍 |
| 新產品線或新裝置類別 | `site-change-required` | 先提案導覽、篩選、頁首文案與搜尋別名，另開網站改版 |
| 來源欄位無法轉成既有維修分類 | `policy-review-required` | 工作簿列出來源欄位、建議站內名稱與合併／獨立理由 |
| 刪除型號、維修項目或品牌 | `policy-review-required` | 不因來源未列出而自動刪除；必須由黑曜明確核准 |
| 改名、合併或拆分既有內容 | `site-change-required` 或 `policy-review-required` | 列出舊值、新值、搜尋相容性與受影響筆數 |
| 單純調整既有項目價格 | `data-only` | 依核准價差政策處理 |

## 結構異動建議格式

每個無法直接套入既有結構的差異，都要在批次下新增一筆：

```text
- 建議編號：
- 類型：新增品牌／新增產品線／新增分類／刪除／改名／合併／拆分
- 來源內容：
- 建議站內位置：
- 建議動作：
- 影響：資料限定／政策判定／網站改版
- 受影響筆數：
- 搜尋與舊連結相容性：
- 目前狀態：待確認／核准／套用／拒絕
- 使用者決定：
```

## 可發布門檻

只有下列條件全部成立，`release-manifest.json` 才能標成 `approved`，並顯示「已可提交 GitHub，但尚未上傳及發布」：

- 來源快照、差異報告與本工作簿的批次紀錄齊全。
- 價格版本、資料雜湊與候選 `prices.json` 完全一致。
- 政策未涵蓋的例外已處理。
- `unresolvedItems` 為空。
- 結構影響只能是 `none` 或 `data-only`。
- 所有結構建議都已套用、拒絕或判定不需要，不能仍是待確認。
- 使用者核准已記錄。
- JSON、重複 ID、分類關聯、資料量與網站建置驗證通過。
