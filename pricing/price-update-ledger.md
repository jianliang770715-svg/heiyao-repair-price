# 黑曜報價更新工作簿

這是報價查詢分頁與網站管理分頁共用的交接紀錄。用途是讓不同分頁知道目前做到哪裡、價格是否完成審核，以及能否接續歸檔與發布；它不是限制彼此行動的權限工具。

## 分頁分工

- **報價查詢分頁**：完成價格蒐集、所有價格增減、品項增刪、未對上項目與需人工確認清單；取得使用者決定後，整理成可交接的價格檔。
- **網站管理分頁**：讀取本工作日誌，負責網站架構、將已確認報價歸檔，以及 GitHub／Cloudflare 上傳發布。
- 工作日誌只負責溝通目前狀態；資料驗證與 GitHub Actions 由網站管理分頁在歸檔／發布時使用，只檢查檔案完整性，不是分頁間的權限門禁。

## 交接狀態

```text
價格收集中 → 待人工確認 → 價格審核完成／可交接
  → 已歸檔／待上傳 → 已提交 GitHub／發布中 → 已發布

價格收集中／待人工確認
  ↘ 有未對上項目
  ↘ 有網站結構建議
```

- 「價格審核完成／可交接」表示報價查詢分頁的工作已完成，不等於已歸檔、已上傳或已發布。
- 網站管理分頁完成正式來源歸檔後，更新為「已歸檔／待上傳」。
- GitHub 已收到提交且正在執行發布時，更新為「已提交 GitHub／發布中」。
- Cloudflare 正式網站驗證成功後，才能更新為「已發布」。

## 新增、刪除與改名判定

| 來源差異 | 判定 | 處理方式 |
| --- | --- | --- |
| 既有品牌、既有產品類別下新增型號 | `data-only` | 可新增型號與報價，不升級網站版本 |
| 既有型號新增可對應既有維修分類的項目 | `data-only` | 可新增報價項目 |
| 新品牌，但現有品牌下拉選單可動態產生 | `policy-review-required` | 先提案品牌名稱、中文別名、排序與承接範圍 |
| 新產品線或新裝置類別 | `site-change-required` | 先提案導覽、篩選、頁首文案與搜尋別名，另開網站改版 |
| 來源欄位無法轉成既有維修分類 | `policy-review-required` | 工作簿列出來源欄位、建議站內名稱與合併／獨立理由 |
| 刪除型號、維修項目或品牌 | `policy-review-required` | 不因來源未列出而自動刪除；必須由黑曜明確核准 |
| 改名、合併或拆分既有內容 | `site-change-required` 或 `policy-review-required` | 列出舊值、新值、搜尋相容性與受影響筆數 |
| 單純調整既有項目價格 | `data-only` | 依核准價差政策處理 |

## 結構異動建議格式

每個無法直接套入既有結構的差異，都要在批次下新增一筆：

```text
- 建議編號：
- 類型：新增品牌／新增產品線／新增分類／刪除／改名／合併／拆分
- 來源內容：
- 建議站內位置：
- 建議動作：
- 影響：資料限定／政策判定／網站改版
- 受影響筆數：
- 搜尋與舊連結相容性：
- 目前狀態：待確認／核准／套用／拒絕
- 使用者決定：
```

## 報價交接資訊

報價查詢分頁交接前應留下：

- 來源快照與差異報告。
- 已套用的價格增減與品項增刪摘要。
- 需人工確認、未對上及使用者決定。
- 可交接價格檔、報價版本與資料量。
- 價格資料驗證結果。
- 是否涉及網站結構，以及給網站管理分頁的建議。
- 明確結論：價格審核是否完成、能否接續歸檔與發布。
